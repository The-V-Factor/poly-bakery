# 资产工具参考

日常使用只需要 [三个动作](assets.md)。需要调整文件规则、删除引用或排查问题时，再看这里。

以下命令从项目根目录运行。Windows 用户把 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。

## 自由选择文件

`.assets.json` 的 `patterns` 使用有序 Git ignore 风格规则，最后匹配的规则优先；以 `!` 开头表示交还给 Git。例如：

```json
{
  "version": 1,
  "bucket": "your-existing-bucket",
  "prefix": "poly-bakery",
  "patterns": [
    "*.blend",
    "*.blend[0-9]*",
    "*.png",
    "*.stl",
    "*.3mf",
    "/arbitrary-location/large.data",
    "!**/renders/*.png"
  ]
}
```

不含斜杠的 `*.blend` 匹配任意层级的文件；开头 `/` 表示相对项目根目录。示例将预览 PNG 留给 Git，把其他 PNG 交给 B2。默认配置也包括 FBX、GLB、JPG、EXR、HDR，且将现有渲染 PNG 与 Blender 备份一起纳入 B2；可以按需要修改。没有体积阈值，也不要求固定资产目录。

修改规则后运行：

```bash
.venv/bin/python tools/assets.py ignore
.venv/bin/python tools/assets.py status
```

`ignore` 只替换 `.gitignore` 的标记区块，并保证工具状态、虚拟环境和 `.env` 被忽略；保留区块外的用户规则。工具会检查选中的文件是否已被 Git 跟踪、是否确实被 Git 忽略，有问题时在联网前报错。不会自动修改 Git 索引或历史。

建议按文件扩展名或文件路径配置，目录中的例外使用 `dir/**` 加具体文件排除规则。与 Git 一样，已忽略整个父目录时，仅写子文件的 `!` 规则不足以让 Git 跟踪子文件；需要先解除父目录的忽略。嵌套 `.gitignore` 也可能影响结果。规则调整后用 `status` 和 Git 检查实际归属。不要把 `.git`、工具控制文件、环境文件或符号链接作为资产。

如需将已有引用交回 Git，先调整选择规则，再明确 `forget` 对应引用，最后运行 `ignore`。如果资产原本已进入 Git 历史，仅添加忽略规则无法移除历史内容；工具会拒绝同时管理 Git 已跟踪的资产，索引与历史迁移应单独处理。

## 删除、改名和冲突

删除资产文件不会被 `push` 自动解释成删除引用。确认删除意图后运行：

```bash
.venv/bin/python tools/assets.py forget 'cyclops/old-model.blend'
```

参数是相对项目根目录的精确路径，不是 glob。`forget` 只改当前清单，保留本地文件和云端对象，旧 Git 提交仍能恢复原内容。如果本地文件还存在且继续符合规则，下次 `push` 会重新加入；需要移走文件或修改选择规则。

改名时，在本地改名后 `forget` 旧路径，再 `push`。因为对象按内容命名，只改名不会重复上传内容。

`pull` 对每个路径比较三份信息：当前清单哈希、本地文件哈希、`.assets-local/state.json` 中上次成功同步的哈希。文件不存在或已等于目标内容时安全；本地仍等于同步基线时可以恢复另一个版本；其他差异一律拒绝覆盖，没有 `--force`。

冲突时，将自己的修改上传到正确的 Git 版本，或者把冲突文件移到项目外临时保留，再 `pull`。新克隆中没有本地状态也能恢复缺失文件；若同时存在未知且不同的文件，工具会保守地拒绝覆盖。不要通过删除状态文件来绕过冲突，它不会使覆盖变得安全。

`pull` 不删除清单外的本地文件，包括新版本有、旧版本没有的文件；切换旧版本后它们可能显示为 `NEW`。如果制作脚本自动扫描目录、必须完全排除这些额外文件，请先自行移走它们。

## B2 权限和历史保留

应用密钥需能访问指定桶，具备 `listBuckets`、`listFiles`、`readFiles`、`writeFiles` 能力；仅下载时不需要 `writeFiles`，生成分享链接还需要 `shareFiles`。可以限制桶和对象前缀。按桶名查找需要允许列出桶名称；工具不需要删除文件或管理桶的权限。

`share PATH --hours N` 分享当前清单引用的内容，默认 1 小时，允许 1–168 小时；本地文件可以缺失，但存在且内容不同时会拒绝分享，避免误发旧版本。命令不上传、不修改清单、不保存链接，标准输出只有 URL，有效期提示写入标准错误。链接中的临时授权按完整对象名作为前缀限制；任何拿到链接的人都能在有效期内下载。该命令仅支持私有桶；公开桶的文件本来就可以公开下载，不能靠临时授权限制访问期限。

B2 Native API 的下载授权用于按名称下载，因此生成链接前会核对该名称当前的文件版本 ID 与清单一致；被外部工具覆盖或隐藏的旧对象会拒绝分享，仍可通过 `pull` 按 ID 恢复。分享期间不要用外部工具覆盖这些内容哈希对象。[B2 下载授权说明](https://www.backblaze.com/apidocs/b2-get-download-authorization)

为资产前缀保留所有历史版本，不要给它配置自动隐藏、过期删除规则。工具本身不会设置桶策略，也没有删除云端对象的命令。外部生命周期规则或手动删除仍会破坏历史恢复能力。[B2 生命周期规则说明](https://www.backblaze.com/docs/en/cloud-storage-lifecycle-rules)

## 清单、去重和失败语义

清单只描述当前版本，示意格式如下（省略了真实哈希和 ID）：

```json
{
  "version": 1,
  "files": {
    "cyclops/CaveCyclops.blend": {
      "sha256": "<64 位 SHA-256>",
      "size": 123456,
      "bucket": "your-existing-bucket",
      "key": "poly-bakery/sha256/ab/<64 位 SHA-256>",
      "file_id": "<B2 返回的具体文件版本 ID>"
    }
  }
}
```

- B2 对象名为 `<prefix>/sha256/<前两位>/<完整哈希>`，相同内容在同一桶、同一前缀下复用。每次新的内容对应新的对象名；清单还固定具体 `file_id`，下载不依赖同名对象的最新版本。并发机器首次上传同一内容可能产生两个 B2 版本，但引用仍稳定；本工具不做分布式锁。
- 上传使用临时快照，SDK 负责大文件分片与传输重试；收到完成版本后再次查询服务端元数据，验证大小和 SHA-256 元数据，所有文件成功后才原子替换清单。如果本地资产或清单在此期间改变，整次清单更新中止。内容传输校验由 SDK 处理，下载另做完整 SHA-256 校验。[官方 SDK 文件操作说明](https://b2-sdk-python.readthedocs.io/en/stable/quick_start.html#file-actions)
- 中途上传失败可能留下已成功上传但暂未引用的对象，下次按内容去重重用，不自动删除。已经失败的大文件上传可能留下未完成的分片，需要时可自行检查 B2；工具没有清理命令。
- 下载先写入项目内的临时目录，所有下载和哈希校验完成，再复查目标文件并逐个原子替换。下载失败或校验失败不会修改目标文件。最终安装阶段若磁盘错误或进程崩溃，可能只恢复了一部分文件，重新运行 `pull` 即可继续；不是跨多个文件的事务。
- `.assets-local/` 不提交到 Git，包含本地凭据 `b2.json`、本机同步基线、操作锁和临时文件，不保存版本历史。正常完成或可捕获异常会清理临时文件；强制终止可能留下 `lock/` 或临时目录。确认没有资产命令运行后，可以删除该锁目录和 `upload-*` / `download-*` 临时目录，保留 `b2.json` 和 `state.json`。
- 传输期间暂停 Blender 保存和 Git 切换。工具会检测传输前后的内容变化，但无法锁住其他程序在最终文件替换瞬间的写入。工具命令之间有本地互斥锁。
- 需要额外磁盘空间：上传时约一个当前资产的临时副本，下载时约所有待恢复资产的总大小。没有永久内容缓存或差分压缩；修改大型 `.blend` 后上传的是完整新内容。
- 每条引用包含桶名，所以改变配置的桶/前缀只影响新上传的内容，旧引用仍指向原桶。恢复旧清单需要对原桶的读取权限。不要删除原桶来“迁移”资产。
